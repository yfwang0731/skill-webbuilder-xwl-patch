# 脚本化生成：什么时候该脚本、怎么收口

本文管**怎么批量产出 `.xwl`**：什么时候值得写脚本、`configs` 的值在哪里归一、
落盘前后各有一道什么闸、换行怎么跟工作区对齐、产物目录要留什么。
单控件的合法配置见 [`controls.md`](controls.md)；几何（面板高 / 列宽 / 工具条）见 [`layout.md`](layout.md)；
值映射见 [`value-mapping.md`](value-mapping.md)。

## 一、什么时候该脚本化

| 情形 | 该不该脚本 | 理由 |
|---|---|---|
| **从零造一整页**（几十个控件、多行、坐标要算） | **该** | 手写坐标极易错位；脚本里可以按 [`layout.md`](layout.md) 的算式算出高度与列宽（面板高度算法、列宽默认值两节） |
| **结构高度相似的两页**（同一套骨架、只差字段） | **该** | 两页共用一个脚本 ＋ 参数化差异，改骨架只改一处 |
| 只改一两个控件、或改一段 SQL | **不该** | 用 `xwl.py patch` 一次就能改；写脚本的维护成本比改动本身高 |
| 存量页面的小修 | **不该** | 脚本重生成会整份重写 ⇒ diff 变成整个文件，评审看不出版面变化 |

> **判据是"新造"与"相似"**：脚本擅长**从零**产出与**成批**产出；
> 对**已有文件的小改**，`patch` 才是默认手段（见 [`SKILL.md`](../SKILL.md) 第三章第 3 步）。

## 二、构造函数统一收口（`configs` 的值全走 `str()`）

**所有节点的 `configs` 都从同一个构造函数出来，值在构造函数里 `str()` 归一。**
`width` / `labelWidth` / `height` / `x` / `y` **全部是字符串**：

| 键类 | 该写成 | ⛔ 别写成 |
|---|---|---|
| 尺寸与坐标（`width` / `labelWidth` / `height` / `x` / `y`） | `"300"` | `300`（数字） |
| 布尔型配置（`hidden` / `autoLoad` / `multiSelect` / `flex`） | `"true"` / `"false"` | `true` / `false`（裸布尔） |
| 其余标量（`text` / `dataIndex` / `itemId` …） | 原字符串 | 数字、`null` |

**为什么必须收口**：加载器按 **String** 取值 —— `configs` 里出现非字符串时页面可能直接崩，
而**手写一处 `str()` 是守不住的**（新增一个键、复制一段代码就会漏）。
收口到构造函数里，`str()` 只写一遍、所有键都过它。

> 这条不是"风格偏好"：`check` 的第 `⑩` 项就是逐值判类型，**任一个值不是字符串即 `FAIL`**。
> 脚本生成的产物一样会被它判 —— 于是"生成期忘了 `str()`"会在**落盘后立刻暴露**。

## 三、双层闸：脚本内断言 ＋ `check`

| 层 | 在哪 | 判什么 | 什么时候响 |
|---|---|---|---|
| **内层（脚本自己）** | 落盘**之前** | 遍历待写对象，**断言所有 `configs` 值都是 `str`**；不满足就**不写盘**、直接抛错 | 生成期（最快的反馈，能指到是哪个节点哪个键） |
| **外层（`check`）** | 落盘**之后** | 同一条类型判据 ＋ 全部格式项 | 手改件、第三方文件、以及内层被绕过的情况 |

**为什么两层都要**：内层只管"本次生成"，管不了**别人手改**与**从别处拷进来的文件**；
外层管得了那些，但它在落盘后才跑（发现时文件已经写下去了）。两层判据**同源**（都判 `configs` 值类型），
所以"内层过、外层红"一定是**外部来源**的文件，定位方向很清楚。

## 四、换行与工作区一致

**按工作区惯例显式指定 `new --eol`**：CRLF 工作区写 `--eol crlf`；LF 工作区可省略。
⚠️ **`new` 的默认是 `lf`，不是 `crlf`**（设计器写在服务器上的产物就是 LF）—— 在 CRLF 工作区里省略它，
拿到的是 LF 文件，`git diff` 会是**整份**。
换行不一致**不会报错**，代价是"整份文件都算改动"。

**判定方法**：改完看 `git diff --stat` 的**改动行数**。

- 改动行数 **≈ 真实改动量** ⇒ 换行对齐了；
- 改动行数 **远超**真实改动量（比如只加了一行、却显示几百行变动）⇒ **换行被换了**，
  用 `git diff --ignore-cr-at-eol` 复核一次确认。

> ⛔ 不要靠"文件看起来正常"判断换行 —— 编辑器会自动适配显示，两种换行看起来一模一样。

## 五、产物目录与可重跑

**把重跑命令写进产物目录的 `README`**：一行命令 ＋ 一句"改哪个参数能改哪一页"。

- 脚本本身**不进产物目录**（版本管理放代码库），产物目录只放：生成出来的 `.xwl`、
  `README`（重跑命令与参数说明）、必要的输入清单；
- **结构相同的两页共用一个脚本 ＋ 参数化差异** —— ⛔ 不要复制一份脚本改几个字，
  否则"改骨架要改三处"和"三处总有一处忘了改"是必然的；
- ⛔ **不要把项目专属的东西写进脚本的参数默认值**（表名、字段清单、坐标数值）——
  它们属于具体工程，换个工程就不成立。

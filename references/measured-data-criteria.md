### 11.2 `diffguard` 加前置必要条件前后的对照

**复现**：在受 git 管理的工程里跑 `xwl.py diffguard <file> --rev <历史 rev>`。

样本 = 某个改过多行 JS 的页面（`wb/modules/…/…xwl`）；
**rev 用 `git log -- <file>` 自取**（挑一个改过多行 JS 的历史提交）：

| | 续行符 | 最长行 | 行数 | 输出 |
|---|---|---|---|---|
| 改前 | 400 → 400 | 146 → 146 | 4470 → 4470 | `[warn] 疑似把多行内容压平（精确命中）` —— **三个计数一个都没变** ⇒ 数学上排除压平 |
| 改后 | 同上 | 同上 | 同上 | rc=0、**0 条精确命中**；`[note] 另有 5 处「内容与基线相邻几行的拼接相同」，但续行符与行数都没减少 ⇒ 判为内容移动 / 复制，不是压平` |

⇒ **修法只降级、不新增告警**：`}` / `';'` 这类**极短行**的拼接是天然的内容匹配误报源，
而 `--strict` 会把这类误报变成 CI 红灯 ⇒ 「续行符数或行数减少」这个前置必要条件是必须的。

### 11.3 `url:` 三类形态的计数

**口径（现值）**：8 个 wb 根（**样本工程全量**）/ **24986 个 xwl** 的**全文正则**扫描（与 §十 相同的 8 个 wb 根 `modules/**`）；
判据 = `\burl\s*:` 逐字命中，其后**裸引号**（`'…'` / `"…"`）与**转义引号**（`\'…\'` / `\"…\"` —— 外层 JSON 字符串里的真引号）都算**字面量**，否则算**动态**；
**未按 JSON 树**、**未剔 JS 注释**。

| 形态（现值口径） | 次数 | 工具是否纳入核对 |
|---|---|---|
| 字面量**含** `m?xwl=` | 30365 | ✅ 已覆盖 |
| 字面量**不含** `m?xwl=`（捷径等） | **440** | ❌ 不核对（只提示） |
| 变量 / 表达式（`url: urlStr` / `app.url.getValue()`） | 867 | ❌ 静态不可能解析 |
| 合计 | 31672 | — |

**口径演变（四组各自自洽；引用时必须写明是哪一组，不可混引）**：

| 组别 | 含 `m?xwl=` | 不含 | 动态 | 合计 | 口径与说明 |
|---|---|---|---|---|---|
| **现值（本轮，工具现行）** | **30365** | **440** | **867** | 31672 | 全文正则；**裸引号 + 转义引号**都算字面量 |
| 工具·修前 | 29720 | 354 | 1598 | 31672 | 全文正则；**只认裸引号** ⇒ 转义引号 731 处（含 645 / 不含 86）**误入「动态」** |
| 本节表格原口径 | 29727 | 355 | 889 | 30971 | 全文正则；要求**裸引号或标识符开头** ⇒ 转义引号**整个不计入** |
| 上一轮口径 | 29738 | 355 | 447 | 30540 | **按 JSON 树**统计（更早） |

⇒ **现值以「现值」组为准**（= 工具现行输出）。**「工具·修前」→「现值」即本轮的修正**：把 `url: \"…\"`（转义引号）731 处从「动态」**重分类**为字面量 ⇒ 动态 1598→867、字面量 30074→30805（两组**合计同为 31672**，只挪不增）。
**现值与「本节表格原口径 / 上一轮口径」不可直接相减**：三者是**不同口径**（原口径的两条正则边界不同、上一轮按 JSON 树），差里混着**口径差**与转义引号两件事 —— 本节只支撑一个结论：**非 `m?xwl` 的字面量 url 有量级（数百处），不是理论上才可能出现**。

- **可复现**：「本节表格原口径」那组值在**同一批 8 根上重跑即可复现** ⇒ 各组之间是**口径差、非时点差**。
- **本轮修因**：`\"` 形态**磁盘上是字面量**（该 JSON 字符串里的真引号）、**静态可解析**；把它算进「动态（静态不可能解析）」是**分类错误**（在载入侧汇总行的用户可见输出里**低报覆盖率**）⇒ 已修 `scripts/xwl.py` 的 `_appearance_url_counts`（`\` 后紧跟引号时按开引号处理），本节与「载入侧汇总行」随之重采为**现值**。

### 11.4 载入侧 `store.url` 的多根三分类（节点级）

**口径**：**8 个 wb 根**（**样本工程全量**）的 `modules/**`（与 §十 / §11.3 **同一批根**；**24986 个 `.xwl`**；排除 `target/`、`.git`），
**按 JSON 树**收集带 `url` 的 `store` 节点（共 **31858 个**），按「url 目标能否在根内解析到文件」分三类：

| 载入侧类别 | 节点数 |
|---|---|
| 同根命中（本根能解析到该 `.xwl`） | **26840** |
| 跨工程（本根没有、别的根里有） | **865** |
| 全根不存在（8 个根里都没有） | **4141** |

⇒ **未纳入核对 = 跨工程 + 全根不存在 = 5006**。（另：非 `m?xwl` 的 url **12 处**；带**前导斜杠**的 `m?xwl` 目标 **6 处**。）

⚠️ **运行时拆不出（多根）三分类**：`params --upstream` 只扫**单根** ⇒ 它的「载入侧」汇总行只给**本根口径**的数
（节点级 同根命中 ／ 本根未找到 ／ 非 m?xwl 的 url —— **三数之和 = 本页 store.url 数**，含「非 m?xwl 的 url」那一类；其中**只有「本根未找到」才是单根口径下「未纳入核对」的那部分**）；上面的**三分口径需多根**，
只有本节（重采）给得出。**两种量纲不可混算。**（起因：同根命中是**纳入**核对的，把它算进「未纳入」会多算 —— 2026-09-23 修正。）

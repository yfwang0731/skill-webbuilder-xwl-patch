# 判据依据、踩过的坑与已作废的做法（**依据层**）

> 本文回答的问题是"**为什么这么定**"：判据的来源、踩过的坑、已经作废的做法。
> 三份材料的**分工**（每一类只在一个地方）：
>
> | 文件 | 只放什么 |
> |---|---|
> | `CHANGELOG.md` | **发版编年**：哪一版改了什么、迁移提示 |
> | [`measured-data.md`](measured-data.md) | **可复现实测值**：数字、样本、统计口径 |
> | **本文** | **因果与作废记录**：为什么有这条判据/守卫、什么做法已被证伪 |
>
> **纪律**：`SKILL.md`、`README.md`、`references/` 其余文件、`scripts/*.py` **一律直接说结论**，
> 不在正文里写"哪天 / 哪一版发生过什么"。本文与上面两份材料是**唯一的例外**（本文允许出现日期，
> 因为它记的就是"什么时候发现了什么"）。这条纪律**有机械守卫**，见第一节。

## 一、编年纪律本身（含守卫）

`scripts/selftest.py` 的文档守卫里有三条臂，扫**全部分发文件**（`git ls-files` 的结果）：

| 臂 | 判据 | 为什么这么设计 |
|---|---|---|
| **施工事件词** | 出现"曾经 / 原先 / 早先 / 以前 / 旧实现 / 旧判据 / 原判据 / 上一轮 / 当时 / 历史上"等词即算违规 | 这些词是编年口吻的**语法特征**；判据看的是**形态**，不看意图 |
| **施工日期** | `YYYY-MM-DD` **必须** ±25 字内有施工动词（实测 / 真机 / 复现 / 审查 / 修正 / 发布 / 事故） | ⚠️ **光有日期不算**：样本里大量日期是**夹具与示例**（聊天时间戳、越界日期样例），宽口径会踩出一片误报、0 收益 |
| **发版号** | **裸三段号**（`\d+\.\d+\.\d+`）一律算违规 | 本仓实测：非 CHANGELOG 的 10 处**全部是编年**；CI 工作流只用两段号（`3.13` / `22`）⇒ **不需要"必须带 `v` 前缀"这条收窄**（别的仓要，因为它们把依赖版本钉进仓库） |

**豁免面**（只有这四类）：`CHANGELOG.md` 全文、`metadata.json` 全文（`version` 与 `update_history`
是契约字段，本来就有版本与日期）、`SKILL.md` frontmatter 的单行 `version:`、以及**依据层两个文件**
（本文与 `measured-data.md`）。

**取不到 `git ls-files` 时**（平台把 skill 打成 zip 分发、本地没有 `.git`）：
**跳过并打印一行 `[note] …本次没扫`** —— 不假装扫过，也不算通过；这层只在 git 仓库里生效。

**已知盲区**（写在守卫注释里，别当成"全都守住了"）：

1. **词表是窄的**：不含上述词根的表述（"上一版"、"旧一版"、"更早的写法"）抓不到；
2. **日期臂要动词**：没有施工动词的日期形命中不了（这是刻意的，见上表的理由）；
3. **豁免面本身可以"开门"**：往依据层文件里写编年是**允许**的 —— 但那是设计而非漏洞，
   因为依据层的定位就是承载这些。

**为什么词表要写成拼接形式**：守卫扫的是全部分发文件，**包括它自己**。整词直接写进
`selftest.py` 的话，本文件会被自己那三条臂判红 ⇒ 词表用相邻字面量拼接（`"曾" "经"`）写，
源码里就不出现完整词。

## 二、判据的因果（为什么这几条必须这么写）

**① 切行必须用 `ANY_EOL_RE`，不能用 `text.split("\r\n")`** —— 加载器接受 `\r\n` / `\r` / `\n` 三种换行；
用后者在纯 LF 文件上切不出行（整份文件成一个元素），会让**逐行检查静默退化成"只看最后一行"**。
这类"只在偏离常见形态时才暴露"的缺陷，样本里长期没被测到，因为纯 LF 在检出形态下很稀少。

**② 写盘命令的自动校验必须跳过 `itemId` 重名（第 ⑦ 项）** —— ⑦ 是文件**既有的质量属性**，
不是本次改动造成的。一并判定会出现"**写盘成功却返回非 0**"的误导。要连它一起体检，单独跑 `check` / `itemids`。

**③ `diffguard` 为什么存在** —— 多行源被压成一行后，文件**自身仍然合法**（不是坏 JSON），
`check` 与事件 JS 校验都会放行 ⇒ "改坏"与"没改坏"在文件自身层面**不可区分**。判据只能换成
**相对 git 基线**。它的精确判据是定义级的：压平 ≡ 删掉「续行符 + 换行」，所以基线里连续多行会原样
变成工作区的一条物理行。另有**粗筛判据**兜"压平同时还改了内容"那一类（两个漏报面的实测数字见
[`faq.md`](faq.md) §三）。

**④ 两个序列化模式都留着** —— 它们**语义等价**（往返解析实测全部等价），
差异**只在字节形态**：默认模式与设计器产物逐字节一致（要提交就得用它），
`--safe` 让值里那处「字面反斜杠 + n」保持原样（人读更直观）。所以选哪个的判据是
"**这个文件给谁看**"，不是"哪个更好"。

**⑤ `--safe` 只给 `expand`，不给 `patch`** —— `patch` 有一条硬承诺"**产出永远是设计器原样**"。
给它加 `--safe` 会让这条承诺失效，而收益只是"读起来顺眼"，不值。要人读的内容
用 `xwl.py sql` / `events` 抽出来即可。

**⑥ "判据依据"断言的 fixture 必须能真的触发被守的行为** —— 断言写对了、跑起来是绿的，
**不代表它守得住**。本仓实测到过一次**假绿**：为守"`@itemId` 不会误指 `configs` 里的内联对象"，
fixture 里放的是 `{"configs": {"itemId": "dup"}}`；而 `_iter_controls` **只 yield `type` 是字符串的节点**，
那个内联对象没有 `type` ⇒ **即使把"跳过 `configs`"那一行删掉，断言照样返回 True**
（实测：注入前后命中数都是 1）。⇒ **判据**：凡声称"注入即红"的断言，fixture 要按**真实形态**造
（真实的内联对象带着 `type`），并且**必须真的做一次注入**去验 —— 否则验的是断言自己，不是实现。

**⑦ `SKILL.md` 的 700 行上限是「护栏」，不是目标** —— 它与 `README.md` 的 150 行上限同源，
**数字是按"留余量"定的、不是量测出来的**；到上限时该做的是**把内容下沉到 `references/`**，
而**不是抬数字**；正常的小幅增补不该触发它。

**⑧ 落点分流纪律（新内容默认去哪）** —— 往 `SKILL.md` 加内容前先判"归哪个通道"：
**只有必用主线步骤才占 `SKILL.md` 的行**（一次典型任务必然用到的：新主线步骤 / 用到处示例 /
适用范围声明 / 定位索引），其余一律走 references：

| 通道 | 只适合放什么 | 跳转代价 |
|---|---|---|
| **A · `references/`** | 判据细节 / 机制复盘 / 对照表 / 边界与退出码 / 实测数字 / 大段示例集 / 契约表 | +1 次文件读 |
| **B · `--help`** | 参数 / 选项 / **用法示例**（不适合"为什么 / 取舍"） | 0 |
| **C · `test-prompts.json` 的 `expected`** | 期望行为 / "该怎么答"（须与行为同批改） | 0 |
| **D · 代码与守卫注释** | 因果 / 机制 / 盲区 | 0 |

> **D 通道的内容会与 `references/` 各存一份 —— 那是守卫机制、不是冗余**：
> 因果 / 机制 / 盲区这类说明，`scripts/*.py` 里必须写一份（读代码、改代码的人要 0 跳转就看见），
> 同时 `references/` 侧也要留一份承载词 —— 因为**文档守卫只扫 markdown**，代码注释它看不见；
> 只有承载词在 markdown 侧也存在，"外移点两侧都还在"（17g）那条臂才有一条真的守得住。
> ⇒ **别把它当"重复内容"合并删掉**：删掉 `references/` 侧那份，那条臂就成了**残臂**（主文档说去哪看、去了却查不到）。
>
> ⚠️ **如实说明这条臂的守备范围**：`17g` 判两件事 —— ① 主文档**该外移点所属小节的区间内**出现目标文件名（局部指针）、
> ② 目标文件里有那几个承载词。其中 ① 按「**锚点小节区间内** contains」判：`selftest.py` 的
> `_splits` 每条 **5 个字段**（末位 = 该外移点在 `SKILL.md` 所属小节的**标题前缀锚点**，**须实测唯一**，共 31 条）；
> 区间由 `_region_after_anchor` 取（= 锚点标题行 → 下一个层号 ≤ 本标题的标题行之间，**跳过代码围栏**），
> **锚点找不到会显式报"这是锚点问题、不是缺指针"**、不静默放行。
> ⇒ ① **仍只证"该小节里出现了目标文件名"、不证"出现的这一处就是那条指针"**；
> ② 只保证"词还在"、不保证"词在 = 该段语义还在"（词可能被改到换了语境）。
> 另：`17g` **只扫 markdown**，读不到 `scripts/*.py` 的注释与 `--help`。**别把 `17g` 绿读成"两侧都真守住了"。**

**⑨ `check ④` 与 `equivalent` 取向不同、**不许统一** —— `check ④` 管"这份文本按加载器规则**能不能加载**"（宽：加载器 org.json 比标准 JSON 宽容）；`equivalent` 管"重建后的**规范化文本**（含键序与值类型）有没有**悄悄改值**"（严：`1` 与 `1.0`、`true` 与 `1`、`-0.0` 与 `0`、键序不同都算不一致）。把两者取向"统一"（例如让 `equivalent` 不比值类型）会**打红 `K8` 的既有断言**，并让"值类型在往返里悄悄漂移"（`1` → `1.0`、整数值浮点被折叠成整数）**重新变成静默通过**。
配套：`_number` 重建时**整数值浮点（含 `0.0`）保真写出 `.0`**（不再折叠成整数）——于是 `expand` / `patch` 对 `{"a":1.0}` / `{"a":0.0}` 由"往返不等、rc=2"改为"往返等价、rc=0"；该面只由**合成样本**触发，真实工程零例（全量「dump → 再解析」用 `==` 与用规范化文本比对结论一致）。

> 上限数字与这条纪律是**一对** —— 数字单独没有意义：不落分流表，任何上限都会被"一律写进 SKILL"破掉。

**⑩ 围栏块里的输出文案也要能比对** —— 输出文案字面既可能写在**行内反引号**里、也可能整段贴在
**代码围栏块**里。只查行内反引号的守卫对**围栏块零覆盖**（绿但空）：把新文案整段放进围栏以规避格式断言，
守卫就**看不见它**了。故围栏块纳入**同一比对**（文案前缀须能在 `xwl.py` 里找到）。
⚠️ **边界（有意）**：该比对用**前缀匹配**，**验不了运行期拼接**出来的文案 —— 拼接结果在源码里
没有字面前缀。`examples/README.md` 里正是这种示意输出 ⇒ 它**不在扫描面内**（扫描面 = docs 的 12 份）。
这不是漏扫，是**扫了会错**。

## 三、已作废的做法（**别再回去**）

| 作废的做法 | 为什么作废 |
|---|---|
| "设计器写的就是 LF" | 真实机制是"**设计器产物换行 = 服务器 JVM 的 `line.separator`**" —— 这只是"在 Linux 服务器上成立"，不是产品固定行为。同理"仓库里存的也是 LF"不可断言：`core.autocrlf=true` 下工作区看到的是 CRLF，**检出形态 ≠ 存储形态**（**Windows 检出形态**与仓库存储形态可能不同，跨平台会变；要引用换行分布须自己用 `git ls-files --eol` 量，样本量级见 [`measured-data.md`](measured-data.md) §五：单行源 902 个、纯 LF 很稀少） |
| 用"最长行显著变长"单条当压平判据 | 两个漏报面实测存在（被压平内容短于已有最长行；压平增量被 ratio 门槛吃掉）⇒ 它只能当**粗筛** |
| 把"`folder.json` 未登记"提升为结论行告警 | 实测未登记比例约一成、样本多是"被调用/被引用的片段页"（本就不该进导航树）⇒ 告警会恒亮，用户无法据此行动。**结论行只报 `index` 悬空项**（登记了但文件不存在）才是真坏 |
| 把 `serverScript` 里的 `{?名?}` 从"SQL 侧需求"里剔除 | 框架取值的唯一去处是 **request**（`WebUtil.fetchObject(request, paraName)`）⇒ 写在哪个字段无关紧要，剔除会把**真实风险静默掉**。正确做法是保留、只按来源分组展示 |
| 只从工程 `controls.json` 推导"哪些类型算取值控件" | 框架运行时看的是**鸭子类型**（控件实例有没有 `getValue`），类型清单只能做近似；而工程注册表**版本会漂移**（同一工程内两个 webapp 也可能不同）⇒ 必须取"注册表推导 **∪** 内置兜底"，否则会出现"**找到了注册表反而更不准**" |
| 把"两个模式**二次 dump 全幂等**"当结论写进正文 | 那是在 **9 类取值**的小样本上测的。换 **1500 个随机结构 × 2 种换行**的属性化模糊测试，「二次 dump 稳定」**546/1500 失败（36.4%）**，反例全部是 `-0.0`（当时 `dumps_designer` 把 `-0.0` 写成 `-0`、`json.loads("-0")` 读回**整数 `0`** ⇒ 二次 dump 不稳；**收口批已改为负零保留 `-0.0`**，该反例不再复现）。⇒ 正文只留"**语义等价**"；两组数字与口径在 [`measured-data.md`](measured-data.md)（**样本量差 167 倍，不能混着引**） |
| 把必须**逐字精确**的键序在多个文件**各列一遍**（当时的理由是"让读者不必跳文件"） | 同一事实留多份副本 ⇒ 任何一处改动都会让其余副本**静默漂移**，而这类漂移在格式层完全合法、**没有任何守卫能报**。改为：主文档留**一份正身**，其余只留**指针**；代价 = 单文件读者多一次跳转。 |
| 在 `references/` 侧各写一份**注册键**的定义句 | **定义只该有一份**（`SKILL.md` 第七章 §7.1）。`references/` 侧保留**因果与机制句**就够了 —— 多份定义同样会漂移，且读者无从判断哪一份是正身。 |

## 四、版本位的约定（含 `2.0.0` 的预留）

- **`major` 是路线图预留位**：`2.0.0` = **配套 Java 后台方法的实现支持**。它**不**表示"破坏性变更"。
- **1.x 内的行为变更**走"三件套"：两阶段（先 `[warn]` 预告、**至少**隔一个已发布版本再翻默认值）＋
  **长期逃生开关**（不是回滚版本）＋ 升级须知（写到"改哪一行"）。
  ⇒ 判据是"**有没有逃生通道**"，不是"落在哪个版本位"。完整表在 `CHANGELOG.md` 文首。
- **现行一例（`create` 开关）**：`patch` 的「新建键」处理正走这条三件套 —— **当前仍允许新建键、只打一行 `[warn]` 预告**；
  后续版本将**翻成默认拒绝**，并新增一个**全局逃生开关**（一次性恢复"全允许"）；逐条放行则用 op 上的
  `"create": true`。⇒ **义务已登记**：翻默认与加开关的那一版，须同时给出升级须知（写到"改哪一行"），
  版本号写在 `CHANGELOG.md`（此处只记因果与义务，不写版本号）。

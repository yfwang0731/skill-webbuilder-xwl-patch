# 判据依据、踩过的坑与已作废的做法（**依据层**）

> 本文回答的问题是"**为什么这么定**"：判据的来源、踩过的坑、已经作废的做法。
> 三份材料的**分工**（每一类只在一个地方）：
>
> | 文件 | 只放什么 |
> |---|---|
> | `CHANGELOG.md` | **发版编年**：哪一版改了什么、迁移提示 |
> | [`measured-data.md`](measured-data.md) | **可复现实测值**：数字、样本、统计口径 |
> | **本文** | **因果与作废记录**：为什么有这条判据/守卫、什么做法已被证伪 |
>
> **纪律**：`SKILL.md`、`README.md`、`references/` 其余文件、`scripts/*.py` **一律直接说结论**，
> 不在正文里写"哪天 / 哪一版发生过什么"。本文与上面两份材料是**唯一的例外**（本文允许出现日期，
> 因为它记的就是"什么时候发现了什么"）。这条纪律**有机械守卫**，见第一节。

## 一、编年纪律本身（含守卫）

`scripts/selftest.py` 的文档守卫里有三条臂，扫**全部分发文件**（`git ls-files` 的结果）：

| 臂 | 判据 | 为什么这么设计 |
|---|---|---|
| **施工事件词** | 出现"曾经 / 原先 / 早先 / 旧实现 / 旧判据 / 原判据 / 上一轮 / 当时 / 历史上"等词即算违规 | 这些词是编年口吻的**语法特征**；判据看的是**形态**，不看意图 |
| **施工日期** | `YYYY-MM-DD` **必须** ±25 字内有施工动词（实测 / 真机 / 复现 / 审查 / 修正 / 发布 / 事故） | ⚠️ **光有日期不算**：样本里大量日期是**夹具与示例**（聊天时间戳、越界日期样例），宽口径会踩出一片误报、0 收益 |
| **发版号** | **裸三段号**（`\d+\.\d+\.\d+`）一律算违规 | 本仓实测：非 CHANGELOG 的 10 处**全部是编年**；CI 工作流只用两段号（`3.13` / `22`）⇒ **不需要"必须带 `v` 前缀"这条收窄**（别的仓要，因为它们把依赖版本钉进仓库） |

**豁免面**（只有这四类）：`CHANGELOG.md` 全文、`metadata.json` 全文（`version` 与 `update_history`
是契约字段，本来就有版本与日期）、`SKILL.md` frontmatter 的单行 `version:`、以及**依据层两个文件**
（本文与 `measured-data.md`）。

**取不到 `git ls-files` 时**（平台把 skill 打成 zip 分发、本地没有 `.git`）：
**跳过并打印一行 `[note] …本次没扫`** —— 不假装扫过，也不算通过；这层只在 git 仓库里生效。

**已知盲区**（写在守卫注释里，别当成"全都守住了"）：

1. **词表是窄的**：不含上述词根的表述（"上一版"、"旧一版"、"更早的写法"）抓不到；
2. **日期臂要动词**：没有施工动词的日期形命中不了（这是刻意的，见上表的理由）；
3. **豁免面本身可以"开门"**：往依据层文件里写编年是**允许**的 —— 但那是设计而非漏洞，
   因为依据层的定位就是承载这些。

**为什么词表要写成拼接形式**：守卫扫的是全部分发文件，**包括它自己**。整词直接写进
`selftest.py` 的话，本文件会被自己那三条臂判红 ⇒ 词表用相邻字面量拼接（`"曾" "经"`）写，
源码里就不出现完整词。

## 二、判据的因果（为什么这几条必须这么写）

**① 切行必须用 `ANY_EOL_RE`，不能用 `text.split("\r\n")`** —— 加载器接受 `\r\n` / `\r` / `\n` 三种换行；
用后者在纯 LF 文件上切不出行（整份文件成一个元素），会让**逐行检查静默退化成"只看最后一行"**。
这类"只在偏离常见形态时才暴露"的缺陷，样本里长期没被测到，因为纯 LF 在检出形态下很稀少。

**② 写盘命令的自动校验必须跳过 `itemId` 重名（第 ⑦ 项）** —— ⑦ 是文件**既有的质量属性**，
不是本次改动造成的。一并判定会出现"**写盘成功却返回非 0**"的误导。要连它一起体检，单独跑 `check` / `itemids`。

**③ `diffguard` 为什么存在** —— 多行源被压成一行后，文件**自身仍然合法**（不是坏 JSON），
`check` 与事件 JS 校验都会放行 ⇒ "改坏"与"没改坏"在文件自身层面**不可区分**。判据只能换成
**相对 git 基线**。它的精确判据是定义级的：压平 ≡ 删掉「续行符 + 换行」，所以基线里连续多行会原样
变成工作区的一条物理行。另有**粗筛判据**兜"压平同时还改了内容"那一类（两个漏报面的实测数字见
[`SKILL.md`](../SKILL.md) §2.6）。

**④ 两个序列化模式都留着** —— 它们**语义等价**（往返解析与二次 dump 的实测结果一致），
差异**只在字节形态**：默认模式与设计器产物逐字节一致（要提交就得用它），
`--safe` 让值里那处「字面反斜杠 + n」保持原样（人读更直观）。所以选哪个的判据是
"**这个文件给谁看**"，不是"哪个更好"。

**⑤ `--safe` 只给 `expand`，不给 `patch`** —— `patch` 有一条硬承诺"**产出永远是设计器原样**"。
给它加 `--safe` 会让这条承诺失效，而收益只是"读起来顺眼"，不值。要人读的内容
用 `xwl.py sql` / `events` 抽出来即可。

## 三、已作废的做法（**别再回去**）

| 作废的做法 | 为什么作废 |
|---|---|
| "设计器写的就是 LF" | 真实机制是"**设计器产物换行 = 服务器 JVM 的 `line.separator`**" —— 这只是"在 Linux 服务器上成立"，不是产品固定行为。同理"仓库里存的也是 LF"不可断言：`core.autocrlf=true` 下工作区看到的是 CRLF，**检出形态 ≠ 存储形态** |
| 用"最长行显著变长"单条当压平判据 | 两个漏报面实测存在（被压平内容短于已有最长行；压平增量被 ratio 门槛吃掉）⇒ 它只能当**粗筛** |
| 把"`folder.json` 未登记"提升为结论行告警 | 实测未登记比例约一成、样本多是"被调用/被引用的片段页"（本就不该进导航树）⇒ 告警会恒亮，用户无法据此行动。**结论行只报 `index` 悬空项**（登记了但文件不存在）才是真坏 |
| 把 `serverScript` 里的 `{?名?}` 从"SQL 侧需求"里剔除 | 框架取值的唯一去处是 **request**（`WebUtil.fetchObject(request, paraName)`）⇒ 写在哪个字段无关紧要，剔除会把**真实风险静默掉**。正确做法是保留、只按来源分组展示 |
| 只从工程 `controls.json` 推导"哪些类型算取值控件" | 框架运行时看的是**鸭子类型**（控件实例有没有 `getValue`），类型清单只能做近似；而工程注册表**版本会漂移**（同一工程内两个 webapp 也可能不同）⇒ 必须取"注册表推导 **∪** 内置兜底"，否则会出现"**找到了注册表反而更不准**" |

## 四、版本位的约定（含 `2.0.0` 的预留）

- **`major` 是路线图预留位**：`2.0.0` = **配套 Java 后台方法的实现支持**。它**不**表示"破坏性变更"。
- **1.x 内的行为变更**走"三件套"：两阶段（先 `[warn]` 预告、隔一个已发布版本再翻默认值）＋
  **长期逃生开关**（不是回滚版本）＋ 升级须知（写到"改哪一行"）。
  ⇒ 判据是"**有没有逃生通道**"，不是"落在哪个版本位"。完整表在 `CHANGELOG.md` 文首。

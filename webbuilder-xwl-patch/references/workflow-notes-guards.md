## 二、判据的因果（为什么这几条必须这么写）

**① 切行必须用 `ANY_EOL_RE`，不能用 `text.split("\r\n")`** —— 加载器接受 `\r\n` / `\r` / `\n` 三种换行；
用后者在纯 LF 文件上切不出行（整份文件成一个元素），会让**逐行检查静默退化成"只看最后一行"**。
这类"只在偏离常见形态时才暴露"的缺陷，样本里长期没被测到，因为纯 LF 在检出形态下很稀少。

**② 写盘命令的自动校验必须跳过 `itemId` 重名（第 ⑦ 项）** —— ⑦ 是文件**既有的质量属性**，
不是本次改动造成的。一并判定会出现"**写盘成功却返回非 0**"的误导。要连它一起体检，单独跑 `check` / `itemids`。

**③ `diffguard` 为什么存在** —— 多行源被压成一行后，文件**自身仍然合法**（不是坏 JSON），
`check` 与事件 JS 校验都会放行 ⇒ "改坏"与"没改坏"在文件自身层面**不可区分**。判据只能换成
**相对 git 基线**。它的精确判据是定义级的：压平 ≡ 删掉「续行符 + 换行」，所以基线里连续多行会原样
变成工作区的一条物理行。"压平同时还改了内容"那一类由**第三条判据（相似度档）**兜：只枚举以续行符结尾的起点、只对完整组
比相似度，且先用 3-gram 松门筛掉绝大多数候选 ⇒ 在最大样本上全量压平也只多 ~0.7s
（另有一条粗筛判据兜"最长行暴增"的形态）。漏报面与实测数字见 [`faq.md`](faq.md) §三。

**④ 两个序列化模式都留着** —— 它们**语义等价**（往返解析实测全部等价），
差异**只在字节形态**：默认模式与设计器产物逐字节一致（要提交就得用它），
`--safe` 让值里那处「字面反斜杠 + n」保持原样（人读更直观）。所以选哪个的判据是
"**这个文件给谁看**"，不是"哪个更好"。

**⑤ `--safe` 只给 `expand`，不给 `patch`** —— `patch` 有一条硬承诺"**产出永远是设计器原样**"。
给它加 `--safe` 会让这条承诺失效，而收益只是"读起来顺眼"，不值。要人读的内容
用 `xwl.py sql` / `events` 抽出来即可。

**⑥ "判据依据"断言的 fixture 必须能真的触发被守的行为** —— 断言写对了、跑起来是绿的，
**不代表它守得住**。本仓实测到过一次**假绿**：为守"`@itemId` 不会误指 `configs` 里的内联对象"，
fixture 里放的是 `{"configs": {"itemId": "dup"}}`；而 `_iter_controls` **只 yield `type` 是字符串的节点**，
那个内联对象没有 `type` ⇒ **即使把"跳过 `configs`"那一行删掉，断言照样返回 True**
（实测：注入前后命中数都是 1）。⇒ **判据**：凡声称"注入即红"的断言，fixture 要按**真实形态**造
（真实的内联对象带着 `type`），并且**必须真的做一次注入**去验 —— 否则验的是断言自己，不是实现。

**⑦ `SKILL.md` 的容量上限是「护栏」，不是目标** —— 现行口径按**字符数**计（硬 **32 000** ／软 **28 000**
字符；另有 **12 000** 字符的远期目标，只作提示、不进判据），它与 `README.md` 的 150 行上限同源，
**数字是按"留余量"定的、不是量测出来的**；到上限时该做的是**把内容下沉到 `references/`**，
而**不是抬数字**。⚠️ **软上限也是判红项**（与硬上限**分别报出**、不合并）：越过它就 `rc=1`，
所以"小幅增补"在**临近**上限时同样会红 —— 那是**提前告警**、不是误报；真被触发时按上一条办
（下沉到 `references/`），⛔ 不要抬数字。

**⑧ 落点分流纪律（新内容默认去哪）** —— 往 `SKILL.md` 加内容前先判"归哪个通道"：
**只有必用主线步骤才占 `SKILL.md` 的行**（一次典型任务必然用到的：新主线步骤 / 用到处示例 /
适用范围声明 / 定位索引），其余一律走 references：

| 通道 | 只适合放什么 | 跳转代价 |
|---|---|---|
| **A · `references/`** | 判据细节 / 机制复盘 / 对照表 / 边界与退出码 / 实测数字 / 大段示例集 / 契约表 | +1 次文件读 |
| **B · `--help`** | 参数 / 选项 / **用法示例**（不适合"为什么 / 取舍"） | 0 |
| **C · `test-prompts.json` 的 `expected`** | 期望行为 / "该怎么答"（须与行为同批改） | 0 |
| **D · 代码与守卫注释** | 因果 / 机制 / 盲区 | 0 |

> **D 通道的内容会与 `references/` 各存一份 —— 那是守卫机制、不是冗余**：
> 因果 / 机制 / 盲区这类说明，`scripts/*.py` 里必须写一份（读代码、改代码的人要 0 跳转就看见），
> 同时 `references/` 侧也要留一份承载词 —— 因为**文档守卫只扫 markdown**，代码注释它看不见；
> 只有承载词在 markdown 侧也存在，"外移点两侧都还在"（17g）那条臂才有一条真的守得住。
> ⇒ **别把它当"重复内容"合并删掉**：删掉 `references/` 侧那份，那条臂就成了**残臂**（主文档说去哪看、去了却查不到）。
>
> ⚠️ **如实说明这条臂的守备范围**：`17g` 判两件事 —— ① 主文档**该外移点所属小节的区间内**出现目标文件名（局部指针）、
> ② 目标文件里有那几个承载词。其中 ① 按「**锚点小节区间内** contains」判：`selftest.py` 的
> `_splits` 每条 **5 个字段**（末位 = 该外移点在 `SKILL.md` 所属小节的**标题前缀锚点**，**须实测唯一**，共 31 条）；
> 区间由 `_region_after_anchor` 取（= 锚点标题行 → 下一个层号 ≤ 本标题的标题行之间，**跳过代码围栏**），
> **锚点找不到会显式报"这是锚点问题、不是缺指针"**、不静默放行。
> ⇒ ① **仍只证"该小节里出现了目标文件名"、不证"出现的这一处就是那条指针"**；
> ② 只保证"词还在"、不保证"词在 = 该段语义还在"（词可能被改到换了语境）。
> 另：`17g` **只扫 markdown**，读不到 `scripts/*.py` 的注释与 `--help`。**别把 `17g` 绿读成"两侧都真守住了"。**

**⑨ `check ④` 与 `equivalent` 取向不同、**不许统一** —— `check ④` 管"这份文本按加载器规则**能不能加载**"（宽：加载器 org.json 比标准 JSON 宽容，**尾随逗号也收**）；`equivalent` 管"重建后的**规范化文本**（含键序与值类型）有没有**悄悄改值**"（严：`1` 与 `1.0`、`true` 与 `1`、`-0.0` 与 `0`、键序不同都算不一致）。把两者取向"统一"（例如让 `equivalent` 不比值类型）会**打红既有断言**，并让"值类型在往返里悄悄漂移"（`1` → `1.0`、整数值浮点被折叠成整数）**重新变成静默通过**。
配套：`_number` 重建时**整数值浮点（含 `0.0`）保真写出 `.0`**（不再折叠成整数）——于是 `expand` / `patch` 对 `{"a":1.0}` / `{"a":0.0}` 由"往返不等、rc=2"改为"往返等价、rc=0"；该面只由**合成样本**触发，真实工程零例（全量「dump → 再解析」用 `==` 与用规范化文本比对结论一致）。

> 上限数字与这条纪律是**一对** —— 数字单独没有意义：不落分流表，任何上限都会被"一律写进 SKILL"破掉。

**⑩ 围栏块里的输出文案也要能比对** —— 输出文案字面既可能写在**行内反引号**里、也可能整段贴在
**代码围栏块**里。只查行内反引号的守卫对**围栏块零覆盖**（绿但空）：把新文案整段放进围栏以规避格式断言，
守卫就**看不见它**了。故围栏块纳入**同一比对**：整行（标签之后的正文，去空白、并抹掉四类可变段 ——
`0x` ＋ 两位十六进制 ／ `position N` ／ `第 N 行` ／ `line N`）须在工具**真跑出来的输出**里
**原样出现**（子串匹配，不是只看开头几个字）。
⚠️ **两条边界（有意，⛔ 别读成"已全覆盖"）**：
① **含任一类占位符的行整行跳过** —— 占位符是**字符类**：**任意一个 `<` 或 `>`** ／ `…` ／ `%s` ／ `%d`
   ／ `...`。也就是说**加一个占位符就退回零校验**；这是**有意的误报控制**（示意行本就带占位符），
   收紧到"整句照比对"要另立条目、⚠️ 这一版**不修**。
② **去空白后不足 8 个字的行直接整行跳过**（这是**免检**，不是判红）；而**抹掉可变段后**不足 8 字的行
   **判红**（"这一行验不了，请写实词"）—— ⛔ 不许用占位把判据掏空。两条门限方向相反，别混。
⚠️ 两处 `continue`（占位符／不足 8 字）**都不计数、不打印** ⇒ "这次跳过了几行"**看不到**。
   ⇒ ⛔ 别把"围栏臂绿"读成"每条围栏输出都验过"。
`examples/README.md` 里是**运行期 f-string 拼出来**的示意输出，其字面在真跑输出里也拼不出来 ⇒
它**不在扫描面内**（扫描面 ＝ 文档守卫的扫描面，`CHANGELOG.md` 除外）。这不是漏扫，是**扫了会错**。

**⑪ `--help` 行数上限是「实测 + 余量」，而且**两侧都判** —— 上限 = 实测 + **5**（顶层 **+10**）。余量的依据是"给某个子命令再加 1 条选项说明留空间"，所以**余量 ≥ 1 就够用**；但**余量本身有上界**：把上限抬到"实测 + 6"及以上（顶层 +11 及以上）就是**白留空行**，而"上限被单向放宽"会让这条守卫**静默失效** ⇒ 上限侧也判红。
⚠️ **这不是"余量必须等于 5"**：余量 ＜ 5（＝上限偏紧、守卫偏严）**不报**。
📌 改 CLI 选项时**先量再填**（量法与守卫一致：`COLUMNS=80`、逐面 `format_help()` 计行）；**新增子命令必须同步登记上限**，漏登会红。

**⑫ 围栏内的跨文件节号指针纳入检查后，**误报面**的真实边界**：该守卫对**围栏内**一视同仁、**零豁免** —— 围栏里写 `<文件名>.md「某个**非原文**小节名」`（哪怕本意只是"示意"）**也会红**。
⚠️ **"当前误报 0"是语料属性、不是判据保证**：它只说明"现有那几处围栏内指针恰好都没问题"。
📌 将来在围栏里写**示意性**指针时：要么把措辞改成不会被判的形态、要么那时再评估加豁免；**别把"基线绿"读成"这类写法安全"**。
